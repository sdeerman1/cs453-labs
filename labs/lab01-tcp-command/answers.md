**1. What is the difference between the client and the server?**  
The client is the program that initiates the communication. The client sends a request and when the request is fulfilled, displays or consumes the results. The server waits for requests and fulfills them. They may have to apply logic or access another resource, such as a database, on the client's behalf. Once the server has the response, it sends it back the client.
**2. Why does the server need to keep running after handling one request?**  
The server may need to handle multiple requests from the same client. The overhead of shutting down and starting up between each request would make the system unusable. They may also need to be available for other clients to connect. In stateful systems, the server must remember each request and context.
**3. What happens if two clients connect at the same time?**  
Each client has a separate connection to the server, and they do not know about each other. The server must be able to handle connections from multiple clients at once and serve each client like they are the only one. So nothing happens if two clients connect at the same time, they can each send requests and receive responses as if they are the only client.
**4. How is this different from HTTP?**  
TCP is used by HTTP, so it is a simpler building block. TCP stands for Transmission Control Protocol, and it simply transmits information. It does not try and understand or do anything with the data it transmits. HTTP stands for Hypertext Transfer Protocol and it uses the same request / response model. HTTP is used on top of TCP in web browsers to format the responses and translate them into visual web content.
